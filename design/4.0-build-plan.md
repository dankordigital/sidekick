# Sidekick 4.0: the build plan

The owner asked for 4.0 on 14 Nov 2026: **the app should look and move like
the prototypes** (the emulator, `design/emulator/`, built from the owner's
Figma design in `design/figma/`), with animations as smooth as the website's,
then **released to GitHub Releases with screenshots of the real app** sent to
the owner. Work through the phases in order. **Each phase ends green**
(`flutter analyze` clean, `flutter test` passing), committed and pushed, so
work can stop at any phase boundary and pick up again. Tick the boxes here as
phases finish (this file is the progress record; HISTORY.md gets a line per
phase).

  scale with a springy release, cards rising in, sheets that follow the
  finger, the sending ring easing, `Hero` between a card and its screen.

## How each screen is built (the owner, 14 Nov: "this looks nothing like the promised design")

**Rebuild, don't recolour.** Each screen is written anew to match its 4.0
design, not the old screen with new colours. For every screen:
1. Open its picture in `design/figma/prototype/` (phone 390×844, e.g.
   `Devices.png`, `Chat.png`, `Send.png`, `Sending.png`, `Remote.png`,
   `Settings.png`, `Incoming files.png`, `Connect · Nearby.png`; computer:
   `Computer · Devices.png` etc.) and its code in
   `design/emulator/emulator.src.html` (exact sizes: titles 30 px bold,
   subtitle line, 22 px panels #1c1c1c holding rows, 48 px device tiles with a
   coloured icon per device, green status #45d07e, white "Send" pills, dark
   "+ Connect" pill, star "Favorites" label, dashed Nearby, the amber "Needs
   you" card).
2. Build it with the same structure, words, sizes and colours. Icons: the
   design's (Lucide-style line icons), not Material's filled ones.
3. Render it (`tool/screenshots_test.dart` with the Chat/Devices sample data)
   and put it **side by side with the design picture** at the same height;
   fix every difference; repeat.
4. Only then tick it, push, and send the owner the side-by-side.

**Less bloated, by Fitts's law** (the owner, 14 Nov: "make app less bloated
looking while keeping the same design and colors. use Fitt's law"): the
same design and colours, with fewer things on each screen and bigger,
closer targets for what's used most. Whole rows are the tap target (a
row opens its device's Chat; Send is a big pill at the row's right edge);
one main action per row, the rest behind a hold (Browse files, Remote, Ping,
Unpair); no extra counts, IP addresses or explanations on screen; primary
actions sit low, near the thumb (the dock, the message bar, Send); nothing a
person taps is smaller than 44 pt.

The dock follows the design too: **Devices · Chat · Send · Remote ·
Settings** (Files is no longer a tab: "Browse files" opens from a device),
with the design's icons.
